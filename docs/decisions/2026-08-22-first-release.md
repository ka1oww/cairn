# What the first release is — 22 August 2026

Decided by the captain, on the answer board, accepting the proposed line:

> Right, so this one kind of detects the minimum that requires for the app to
> run and then all other features we can edit through PR pushes

## The decision

**The first release is whatever makes one real trip work for eight people.**
Nothing else qualifies, however good it is. Everything else lands afterwards,
one pull request at a time.

## In — the minimum for one real trip

- Eight people can join with three spoken words
- The itinerary is pasted once, and everyone can read today
- Everyone's pocket buzzes at their own minute
- Taking a photo opens today's page
- The photos land in one pool everybody can see

## Out — version two, and not one of them is a loss

- **The book.** The payoff and the reason the app exists to argue for — but it
  is made *after* the trip, from photos already sitting in a pool. It does not
  need to exist while anyone is travelling. That is what makes this line
  drawable at all.
- Authored words, [the cat](2026-08-22-cat-deferred.md), the handover, the
  two-frame camera, the countdown.

## The test it is held to

When a friend on the trip asks what this does, one sentence answers it. If the
answer needs two sentences, something on the "in" list belongs on the "out"
list.

## Why this matters more than it looks

Before this, thirty-odd queued jobs were all good ideas and none of them was
more necessary than any other. This line is what makes the queue orderable.
Anything not on the "in" list is now explicitly allowed to wait, and saying so
is the point. `docs/roadmap.md` is reshaped around this line.
