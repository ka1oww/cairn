# The book is automatic, and there is no editor — 22 August 2026

Decided by the captain, accepting the recommendation.

## The decision

**The book generates itself. Nobody edits it.**

It prints the words people had already written when they took the photo. There
is no book-editing surface, no layout controls, no rearranging pages, no
"customise your book" flow.

## What the captain actually spotted

> i think the book maybe should be automatic? but if they want to edit it then
> wouldnt that be more features we need to add in such as having an editor?
> maybe let keep it simple and not allow that?

He was right that an editor is a whole feature rather than a detail, and right
to be suspicious of how it arrived — it arrived by implication from his own
earlier "yes, people may write their own words" in
[book round nine](2026-08-22-book-round-nine.md), not by anyone proposing it.

## The distinction that resolved it

Authored words and a book editor are not the same feature, and collapsing them
was the error.

- **A caption typed when the photo is taken** is a text field on a screen that
  already exists. The book prints whatever is there. Cost: near nothing.
- **A book editor** is a second authoring surface with layout, ordering, and
  revision. Cost: a real feature.

So the book stays automatic and keeps the human writing, because the writing
was never happening in the book.

## What this closes, and what it does not

**Closed:** no book editor, now or later. If it is ever revisited it is a new
feature with its own argument, not a restoration of something implied.

**Still open:** the book's treatment — generated, handmade, or the derived
blend. This decision deliberately does *not* close it. The case against the
handmade look was that a generated book contains no human labour; captions are
human labour, so that argument stays weakened and the fork stays live. It
belongs to design round ten.
